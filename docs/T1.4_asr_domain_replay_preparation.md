## Selection and fallback

On the eventual GPU run, evaluate the original133 parent and expanded134 initial model separately, on the same validation audio/precision. Expansion preserves all old tensors/head rows but may change softmax and decoding; baseline parity is not assumed. The baseline for acceptance is the **original parent133**.

An updated checkpoint is eligible only if WER and CER for all4 sources do not regress, **both domain WER and CER strictly improve**, and the unweighted mean WER improves. Select the lowest eligible mean validation WER. Rejected metrics cannot replace an eligible best. If none qualify, `best.pt` retains the original133 model tensors/config/vocabulary at step0; an untrained134 head must not become the fallback. `last.pt` may contain a rejected134 model and must not be deployed. The output selected vocabulary is reconstructed from the actual selected checkpoint, including the133 fallback case.

The trainer evaluates full30-second domain clips. Its newly measured same-GPU baseline is not required to equal the earlier cached CPU production diagnostic, which used20-second windows. The report keeps the domain development scope explicit. Original3-domain tests are evaluated only after checkpoint selection; there is no invented domain test, test-derived vocabulary or test-based weight selection. Production-window/human assessment remains a separate evaluation after training, before any promotion.

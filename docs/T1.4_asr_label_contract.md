# T1.4 — Lossless ASR labels and preflight

Status: **DONE — STRICT LABEL ENCODING / PREFLIGHT VERIFIED** (2026-10-20). This fixes training-label loss; it does not claim an acoustic recognition improvement or deploy a new model.

## Label convention: asr-label-v1-lossless

Use the existing `ai_core.scripts.prepare_asr_robust.normalize` for newly prepared labels: NFC Unicode, uppercase, collapsed whitespace. Preserve the source transcription alongside normalized text where available. `CharVocab.encode` itself performs no normalization or rewriting.

- Keep English words, acronyms and proper names in the audio-supported transcription; case normalization does not translate them or replace them with guessed Vietnamese spellings.
- Preserve the reference's written number/date/percentage/identifier form. `9,4%`, `2020` and `08-NQ/TW` stay intact; a reference written as Vietnamese number words stays in words. The encoder does not convert between spoken words and written digits, change decimal separators, expand abbreviations, infer legal identifiers or repair place names. These examples illustrate encoding and are not verified legal citations.
- Human reviewers must resolve exact values/identifiers from audio and mark uncertainty instead of guessing. Formatting aliases and inverse text normalization need a separately specified evaluation policy; they are not silently equated in WER/CER.
- Reject unsupported training characters, missing text and empty/whitespace-only labels. Report sample path/split and unsupported Unicode code points. Do not skip the sample or delete its characters to make training continue.
- Build vocabulary additions from training data only. Preserve existing symbol IDs and validate checkpoint/head dimensions when explicitly creating a new candidate. Do not append validation/test characters or edit an active vocabulary file to make an old head appear compatible.
- Evaluation retains raw reference text, including characters absent from the training vocabulary. Such characters remain errors in WER/CER. This task never rewrites frozen validation/test labels.

The existing93-symbol active and133-symbol candidate checkpoints remain unchanged. Character coverage is separate from acoustic accuracy and label provenance. The user's Whisper-assisted review remains diagnostic/unapproved; passing a vocabulary check does not make it accepted training data or create human-written summaries.

## Implementation

`CharVocab.encode` now raises `ValueError` for unsupported symbols. The former `FTA→TA`, `WTO→TO`, `2020→empty` and `9.4%→4` label conversions are refused. Supported strings retain the same IDs and roundtrip text.

`ASRDataset` validates every selected training label during construction, before audio decoding, data workers or model/GPU training. Both the general trainer and the robustness recipe use this path. Errors include the offending sample path and split.

The shared `ReferenceASRDataset` reads features and preserves the complete reference string, without encoding a truncated target. It permits only validation/test splits without augmentation. Its empty target tensors are collator placeholders, not CTC training targets. Both the general trainer's ASR WER callback and the robustness evaluator use raw reference text. Existing training batches still use the same four CTC tensors. The feature extraction/augmentation implementation is shared; raw audio processing and inference decoding are unchanged.

This also corrects general validation scoring: it no longer reconstructs reference text through the model's limited vocabulary. Future scores can therefore expose errors previously hidden by that reconstruction. Historical scores were not recomputed or edited. The existing robustness evaluator already scored raw text; that behavior remains covered by tests.

## Lỗi đã tái hiện và sửa

`GPUQueue._run()` giữ `fn`, `fut`, `result` của job cuối trong coroutine frame khi đang chờ `queue.get()` tiếp theo. Do đó request closure/response có thể sống lâu hơn request, kể cả lúc queue depth=0. Đây là giữ bộ nhớ cuối job; không suy diễn thành tăng RAM vô hạn mỗi video.

Regression bằng `weakref` + payload 1MiB đã FAIL trên code trước sửa: `idle GPU worker retains last request closure`. Sửa nhỏ trong `finally`: giải phóng cả ba tham chiếu sau `task_done()`. Test sau sửa xác nhận request và response đều được thu hồi khi worker idle; exception vẫn propagate và job kế tiếp vẫn chạy.

Thêm trace nội bộ opt-in `INFERENCE_MEMORY_TRACE=1`: mỗi stage ghi RSS/VmHWM, PID, device, CUDA allocated/reserved và peak allocated/reserved kể từ process start. CPU giữ trường CUDA là `null`. Không thêm endpoint/field OpenAPI hay sửa ports. Không reset peak stats, gọi `empty_cache()`, ép GC hoặc restart service trong benchmark.

## Chạy lại trên máy hiện tại

```powershell
$env:INFERENCE_MEMORY_TRACE='1'
docker compose --env-file .env -f docker-compose.yml up -d --build --wait --wait-timeout 60 inference-service ingest-worker
$env:E2E_MEMORY_RUN='1'
# Optional: a local input video; otherwise use the second 8-second fixture.
$env:E2E_MEMORY_VIDEO='E:/traning_ai/test-results/t43-sources/user-video.mp4'
npx playwright test e2e/inference_memory.spec.ts --output=test-results/t43-memory --reporter=list
Remove-Item Env:INFERENCE_MEMORY_TRACE
docker compose --env-file .env -f docker-compose.yml up -d --no-deps --wait --wait-timeout 60 inference-service
```

Điều chỉnh/loại bỏ `E2E_MEMORY_VIDEO` nếu chạy trên máy khác. Dữ liệu test dùng soft deletion: DB rows và MinIO objects còn như chính sách T4.1; vector live và scratch được dọn. Fixtures được tái sử dụng có chủ đích để giữ shape cố định, không dùng số lượng 20 upload để tuyên bố 20 mẫu nội dung độc lập.
